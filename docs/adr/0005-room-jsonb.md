# 0005 방은 jsonb 통째 저장

2026-11-23 확정

## 결정

- 방 하나는 `rooms` 한 줄, 가구·문·창문은 `data` jsonb 안에
- 가구 테이블 따로 두지 않음

## 근거

- 방은 늘 통째로 열고 저장
- 실행 취소·자동 저장이 방 상태 하나로 끝남
- 구조 변경은 `schemaVersion`으로 - SQL 마이그레이션 불필요

## 대안

| 대안           | 기각 이유                                |
| -------------- | ---------------------------------------- |
| 가구 행 테이블 | 바뀐 행 추출·저장 RPC 필요, 변경마다 SQL |

## 트레이드오프

- 동시 편집을 합치지 못함 (0004)
- 통계·상품 id 무결성은 DB가 못 지킴
- 공동 편집이 생기면 다시 검토

## 가구 테이블 대비

- 가구마다 고유 `id` 유지 - 행 키로 그대로 쓸 수 있게
- Supabase 호출은 api에서만 - 저장 방식이 바뀌어도 편집기는 그대로
- api는 `Room`을 통째로 주고받는 모양 유지
