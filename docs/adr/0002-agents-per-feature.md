# 0002 개발 에이전트를 기능 단위로 나눔

2026-11-12 확정

## 결정

- 에이전트 하나가 기능 하나 전체 담당 - core·api·web·디자인·동작 확인
- 의존 없는 기능만 병렬, 브랜치·PR은 기능마다
- 리뷰는 reviewer가 따로

## 근거

- 계층별 분담은 성능·비용 이점 없음
- 넘길 때마다 계획 재설명, core 완료 후에야 다음 시작이라 사실상 순차 진행
- 문제는 주로 타입·API 경계에서 발생 - 한 에이전트가 양쪽을 보는 편이 유리

## 대안

| 대안           | 기각 이유            |
| -------------- | -------------------- |
| 계층별 분담    | 전달 비용, 순차 진행 |
| 메인 세션 단독 | 병렬 불가            |

## 트레이드오프

- 에이전트 하나의 문맥 증가 - 기능을 작게 잘라 대응
- `.pen` 시안·저장 구조·마이그레이션을 함께 고치는 기능은 병렬 불가
