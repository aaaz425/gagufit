# feature

메인 세션이 PM 역할 - 직접 구현하지 않고 기능을 나눠 dev에 맡김

## 1. 나누기

- PRD·로드맵·관련 코드 확인 후 서로 의존 없는 기능으로 분리
- 같은 파일을 고치는 기능은 병렬 금지 - `.pen` 시안, 저장 구조, 마이그레이션, 공용 타입
- 의존이 있으면 한 기능으로 합치거나 앞 PR 머지 후 진행

## 2. 계획

- 기능별 목표, 범위 밖, 병렬 여부
- 사용자 확인 - 이후 PR 초안까지 확인 없이 진행
- 계획에 없던 범위 변경이 생기면 그때만 다시 확인

## 3. 구현

- 시작 전 `git fetch origin`, 기능 브랜치는 `origin/main`에서
- 시작 전 머지된 기능의 worktree·로컬 브랜치 정리
- 기능마다 dev 하나, Agent `isolation: "worktree"`
- 병렬 가능한 기능은 한 번에 실행
- 전달은 해당 기능 계획만

## 4. 리뷰

- 기능 브랜치마다 reviewer
- 반드시 고칠 것은 SendMessage로 같은 dev에게 - 최대 2회, 넘으면 사용자에게 보고
- 제안 수준 지적은 사용자에게 보고하고 넘어감

## 5. 기록

- 되돌리기 어려운 구조 결정이 있었으면 `/adr`
- 로드맵 해당 단계 체크

## 6. PR

- 기능마다 `/pr` - 초안 확인 후 생성, 머지는 사용자
